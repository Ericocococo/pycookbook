## 1. 真实架构总览（映射基准）

```
策略代码（demo\ 下两种形态）
  single:     def macd_strategy() 无参 + 模块级 ntdata/nttrader
  lifecycle:  init(ctx) / after_init / handlebar(ctx, bar_dict) / on_stop
      │ 扁平导入注册 strategy_loader.install_strategy_import_aliases()
      │ (ntdata→ntrade._impl.ntdata, ntcontext→ntrade.interface.ntcontext ...)
      ▼
共享转发层（一份实现，两路径共用）
  ntrade\_impl\ntdata.py     → get_current_context().data_provider.xxx()
  ntrade\_impl\nttrader.py   → get_current_context().broker.xxx()
      ▼
线程本地全局上下文
  ntrade\_impl\_runtime\nt_context.py
    NtTradeContext.backtest(BacktestConfig) / .live(LiveConfig)  ← 工厂 + 延迟导入
    set_current_context / get_current_context / clear_current_context  ← threading.local
    BaseDataProvider / BaseBroker（ABC）
    NtTradeContext.run(): set_current_context → 按 mode 分派 → finally clear_current_context
      ├── 回测：ntrade\_impl\backtest\_adapter.py NtBacktestAdapter
      │        → _broker.py NtBacktestBroker（委托 C++）+ _data_provider.py（6 个 Mixin 组合）
      │        → C++ 引擎（quant.core.frame 的 submodule，本仓不读细节）
      └── 实盘：ntrade\_impl\livetrade\_engine.py 等 —— ⚠️ 全是桩（NotImplementedError）
```

**与教学最相关的真实文件速查**（想对照源码从这里进）：

| 想看的机制 | 文件 | 重点 |
|---|---|---|
| 全局上下文/工厂/ABC | `ntrade/_impl/_runtime/nt_context.py` | set/get/clear + threading.local + 两类 factory + 基类分级能力（抛错三态） |
| 模块级转发 | `ntrade/_impl/ntdata.py` `nttrader.py` | 每个函数一行 `get_current_context().xxx` |
| 回测装配 | `ntrade/_impl/backtest/_adapter.py` | 加载数据 → 包装策略 → 绑 C++ 回调（wrapper 生命周期最全） |
| 数据提供者拆分 | `ntrade/_impl/backtest/_data/` | `_provider.py` 组装 `NtBacktestDataProvider`，6 个 Mixin 每维度一文件（`_market/_calendar/_sector/_financial/_stock_info/_l2`） |
| 双模式探测 | `ntrade/_impl/strategy_loader.py` | 按函数名探测 lifecycle/single + 扁平导入注册 + overrides |
| 策略协议 | `ntrade/interface/ntcontext.py` | INTradeContext(Protocol) 全接口签名 + BarDataView |
| bar 内时序 | `quant.core.frame/.../engine_impl.cpp` `OnStrategyNext` | 撮合 → on_market_open → open_next → 换日清算 → next()（红线 2/3 依据） |
| 权威设计文档 | `doc/ntrade/design.md` | 2026-07 早期设计（四条原则：C++ 零侵入/接口不动/策略无感/一处切换）。⚠️ 与现行代码有多处**演进差异**（详见 §6 注记 09），对照本文档阅读 |
| 真实策略样板 | `demo/ntrade_macd.py` `ntrade_macd_lifecycle.py` | **给学习者抄作业的样本**：single 版含扁平导入 + xtquant→ntrade 迁移映射表；lifecycle 版含 init 参数写法 + 双参 handlebar + 别名钩子（05/06 对照） |

## 2. 现有 demo 逐阶段体检

结论分级：✅ 主线正确　⚠️ 有偏差（教学上会误导）　❌ 缺失

### 01_global_context —— 全局上下文 + 模块级转发

| 维度 | 结论 | 说明 |
|---|---|---|
| 教学主线 | ✅ | 模块级函数一行委托 + set/get 切换，与真实 `ntdata.py/nttrader.py` 一致 |
| 并发机制 | ❌ **要改代码** | 真实是 **threading.local**（每线程独立上下文）；01 两个 demo 与 06 的 context.py 都用"全局变量 + Lock"。Lock 只保证写互斥，不隔离线程——并发回测（如服务端线程池）时 A 任务 set、B 线程会 get 到 A 的上下文。demo 注释还把 Lock 讲成"线程安全"，把真实机制教反了 |
| 生命周期 | ✅ | demo_01 运行段 try/finally、demo_02 用 @contextmanager 包 set/clear，与真实 `run()` 的 finally clear 思路一致 |
| 未初始化行为 | ✅ | 两个 demo 均已演示 `RuntimeError`（demo_01 L74-75、demo_02 运行段验证）——初版体检误标 ❌，已更正 |

**修正动作**：全局上下文改用 `threading.local`（01 两文件 + 06 context.py 同步），演示"并发隔离"对照。

### 02_abc_factory —— ABC + 工厂 + 延迟导入

| 维度 | 结论 | 说明 |
|---|---|---|
| 教学主线 | ✅ | `backtest()/live()` 工厂 + 延迟导入，与真实 `NtTradeContext` 一致 |
| 基类能力分级 | ⚠️ 半覆盖 | demo_01 已演示"默认实现抛 NotImplementedError"（subscribe_realtime），方向对；缺真实的分工讲解：**仅实盘能力 → 抛 `NotSupportedInBacktestError`**（如 subscribe_quote），**尚未实现 → 抛 `NotImplementedError`**（如 get_financial_data），另有**静默降级第三态**（如 `cancel_order_stock_sysid` 回测返回 -1 而非抛错）。三种能力语义不同，值得补 |
| 实盘桩现状 | ⚠️ | demo_02 的 LiveProvider 返回模拟数据、一切正常——但真实 `live()` 能创建、进 `LiveEngine.start()` 后 NotImplementedError。**实盘是对接口形状的预留**，docstring 需声明，否则读者以为真能实盘 |
| 配置合并规则 | ❌ | 真实"外部 config 非空覆盖 init 里设的值、外部没给 symbols 回退 init 自设"的合并规则没讲（可一句话点到，非重点） |

### 04_bar_engine —— 逐 bar 引擎

| 维度 | 结论 | 说明 |
|---|---|---|
| 教学主线 | ✅ | "回测 = for 循环逐 bar + 回调策略"方向正确（真实主循环在 C++ `run_multi`） |

## 3. 教学红线 —— 五个最容易讲错的地方

任何 demo 的 docstring / README 若与下面五条冲突，以本表为准改：

1. **backtest 与 livetrade 不是"各存一份 ntdata/nttrader"** —— 两路径的 `__init__.py` 只是 re-export `_impl` 的**同一份**共享实现（源码注释原文："backtest/ntdata.py 和 livetrade/ntdata.py 均从此导入"）；并存的只有两对 provider/broker，分支点在 `NtTradeContext.backtest()/.live()` 工厂。
2. **下单不是"当日收盘价成交"，且挂单只撮合一次** —— `engine_impl.cpp`（已源码核实）：T 日 `next()` 挂单 → 引擎先推进 T+1 行情 → T+1 开头 `ManageActions()` 撮合（`try_match` 规则：**市价单成交价 = 次 bar 开盘价**；**限价单 `lp ≥ low`(买)/`lp ≤ high`(卖) 即成交，成交价 = 限价本身**——引擎不做"更好价"优化；一字板 high==low：涨停拒买、跌停拒卖，**退市股一字跌停仍可卖**（清仓用）；滑点在 C++ 应用：`成交价 ×(1±slippage_bps/10000)`，买加卖减）→ 换日清算 `m_orders.clear()` 未成交作废（当日有效单）。注：C++ 另保留 `open_next` 阶段（引擎注释自称"作弊入口"，enable 时其挂单当日成交）；ntrade 的包装器 `open_next` 为空、策略走 `next()`，故正常路径即次日撮合。"作弊入口"是早期设计的执行点残留——design.md（2026-07）原文策略绑在 `open_next`（紧跟第二个 ManageActions → 当日成交），现行实现把策略挪到 `next()`（清算后 → 次日撮合），open_next 只剩兼容空壳（见 §6 修订 09）。
3. **防未来函数不是"Python 按时间截断"** —— 已全链路源码核实：主循环每 slice **先 `update_last_day_quotes` 把当日行情推进进 HisBarMgr、再 `OnStrategyNext()` 回调策略**（两处同构）；Python 取数 `_get_hist_df` 走 C++ `to_df_ref_last(false)` 的 `iloc[:cur_size]` **只增零拷贝视图** + 增量 copy 缓存（行数未变直接返回同一对象，增长仅拷贝新增行，防 O(B²) 退化且不污染 C++ buffer）；`get_cur_bar`/`get_cur_slice` 是仅当前 bar 有效的零拷贝视图（interface 注释原文："仅当前 bar 内有效, 勿跨 bar 保存"）；连 fill_data 停牌填充也"日历范围截至 df 末尾, 天然防未来函数"。讲"数据只增不减 + 回调时机"而不是"框架帮你截断"。
4. **实盘层是桩** —— `LiveEngine` 模块 docstring 原文即"实盘事件驱动引擎（桩）"，`start()` 抛 NotImplementedError"待实现"。"同一份策略回测/实盘切换"目前只对回测成立；live 路径是接口形状预留。
5. **broker 的查询"看似透传、实则 Python 侧维护语义"** —— `NtBacktestBroker`（已源码核实）：C++ 盘中不结算（当日买入当日并入 position、`available_size` 含当日买入），Python 侧 `_day_buy_volume` 登记当日买入量、查询路径按它扣减还原 T+1 可卖（回调路径天然 T+1，两路径经此口径一致）；`_order_registry` 委托登记表是 `query_stock_orders` 主数据源（C++ `get_orders()` 只留挂单队列，成交即擦除）；`_trade_records` 成交登记回调/查询同源。**关键细节：真实换日不清当日买入登记**——`_day_buy_volume` 按 `{symbol: {交易日期: 量}}` 键存，查询按"当前日期键"匹配、旧日期自然失效（且 C++ 换日回调在当日撮合之后触发，清空会误清新撮合的当日买入）。mini 框架用"每日显式清空"做语义等价简化，但注释不得写成"对应真实清空登记"。mini 应保留这层语义，不要退化成纯转发。

> 补充一条易漏：**配置来源优先级** —— 外部 `set_backtest_config()` 非空才覆盖 `init(ctx)` 里设的值；外部没给 symbols 时回退用 init 自设的。`stock_code ↔ symbols` 等别名双向同步。
