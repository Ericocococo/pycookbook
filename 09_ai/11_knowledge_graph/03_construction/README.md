# 03_construction 图谱构建 —— 从文本抽三元组

> 图谱的"原材料"是文本：新闻、财报、百科条目。构建 = 从非结构化文本里
> 抽出结构化三元组。最古老的方法是规则，现代主流是 LLM（大模型）抽取。
> 本目录先学规则法（把机制讲透），再了解 LLM 路线。

| 文件 | 内容 |
|------|------|
| [01_rule_extraction.py](01_rule_extraction.py) | 规则抽取流水线：词典 NER → 触发词关系抽取 → 组装图谱 |

## 1. 知识点

### 1.1 抽取的两个步骤

| 步骤 | 英文 | 干什么 | 输入 → 输出 |
|------|------|--------|------------|
| 实体识别 | NER | 从文本挑出"谁/哪家公司/哪个城市" | "马云创立了阿里巴巴" → 人物:马云 公司:阿里巴巴 |
| 关系抽取 | RE | 判断两个实体间是什么关系 | (马云, 阿里巴巴) + 中间词"创立了" → 创始人 |

流水线：文本 → **NER** → 实体对 → **关系抽取** → 三元组 → 入库成图

### 1.2 三条技术路线

| 路线 | 做法 | 特点 |
|------|------|------|
| 规则法（本目录） | 词典 + 正则模式 | 零训练、可控，但词典和模板要人维护 |
| 机器学习 | CRF/BiLSTM-CRF 做 NER | 要标注数据训练 |
| 大模型（现代主流） | 把文本和 schema 丢给 LLM 返回 JSON | 零标注、效果最好，见 [05_application/02_graphrag.md](../05_application/02_graphrag.md) |

> 规则法现在依然有价值：① 讲原理最清楚 ② 词典受限领域（公司名表）很准
> ③ 给 LLM 做预过滤/兜底。学习顺序建议：规则法 → LLM 法。

## 2. 运行

```bash
python 01_rule_extraction.py   # 纯 Python 标准库，零依赖
```

## 3. 术语速查

| 词汇 | 全称/英文 | 说明 |
|------|------|------|
| NER | Named Entity Recognition | 命名实体识别：人名/地名/机构名等实体的抽取 |
| RE | Relation Extraction | 关系抽取：判断实体间语义关系 |
| 词典法 | Dictionary-based | 用预置词表匹配实体，最简单 NER |
| 触发词 | Trigger word | 连接两实体的动词，提示关系类型（"创立了"→创始人） |
| 流水线 | Pipeline | 先 NER 后 RE 的分步处理结构 |
